## Problema

Al arrastrar y soltar un evento recurrente (ej. "Almuerzo" 13:00 diario), el sistema aplica `updateActivity` directamente sobre esa ocurrencia sin preguntar al usuario si desea mover **solo ese día** o **toda la serie**. El usuario no tiene control de scope en el flujo DnD.

## Contexto del código

**Archivo clave:** `app/(app)/calendar/_components/CalendarClient.tsx`

`handleDropEvent` (línea ~1343) actualmente:
```typescript
// Solo maneja scope single — sin detección de recurrencia
const { updateActivity } = await import('@/actions/calendar')
await updateActivity(eventId, { date, time, duration, ... })
router.refresh()
```

**Patrón existente a reutilizar:**
- `pendingCascade` state (línea ~1284) — mismo patrón de "confirmar antes de ejecutar"
- `editScope: 'single' | 'all'` en `EditActivityModal` — misma semántica
- `recurrenceGroupId` disponible en `ICalendarEvent` para detección

**Server actions disponibles:**
- `updateActivity(id, data)` — mueve ocurrencia individual (ya existe, ya acepta date+time)
- `updateActivityGroup(groupId, data)` — actualiza grupo pero **NO acepta date/time**

**Gap identificado:** No existe server action que actualice `time` en toda la serie recurrente. Se necesita crear `updateGroupTime(groupId, newTime)` o extender `updateActivityGroup`.

## Acceptance Criteria sugeridos

- **AC1:** Al soltar un evento recurrente, antes de ejecutar el move, aparece un mini-popup (no modal) con 2 opciones: "Solo hoy" / "Toda la serie". El evento vuelve a su posición original si el usuario cancela (click fuera o Escape).
- **AC2:** "Solo hoy" → llama `updateActivity(eventId, { date, time, ... })` — mueve solo esa ocurrencia.
- **AC3:** "Toda la serie" → llama una nueva acción que actualiza el `time` en todas las ocurrencias del grupo (`recurrenceGroupId`). La fecha de cada ocurrencia permanece igual; solo cambia el horario.
- **AC4:** Eventos NO recurrentes → comportamiento actual (move directo, sin popup).
- **AC5:** Durante el popup, el evento se muestra en el slot destino con opacidad reducida (preview) hasta confirmar.
- **AC6:** 0 errores typecheck, lint limpio.

## Scope técnico

**IN:**
- Nuevo estado `pendingDrop` en `CalendarClient`
- Popup inline (sin modal/dialog HTML nativo) sobre el slot destino
- Nueva server action `updateGroupScheduleTime(groupId, newTime, duration)` en `actions/calendar.ts`
- `handleDropEvent` refactorizado para detectar `recurrenceGroupId`

**OUT:**
- Cambio de fecha en "toda la serie" (ej. mover lunes→martes toda la semana)
- Recurrencias en AgendaView o MonthView
- Undo/redo del drop
