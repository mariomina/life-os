# Brief Técnico — Story 10.17: Bug — Edición de Horario Bloqueada

**Para:** @sm (River)
**Épica:** 10 — Calendario avanzado

**Preparado por:** @analyst (Atlas)
**Tipo:** BUG — Crítico

## Síntoma reportado

El usuario intenta cambiar el horario de una actividad de **14:45–15:30 → 13:45–14:30** y el sistema no persiste el cambio. La interfaz aparentemente acepta la edición pero el horario no se actualiza.

## Diagnóstico del código

Análisis de `EditActivityModal.tsx` y `actions/calendar.ts`:

### No hay validación que bloquee explícitamente

- `calcDuration("13:45", "14:30")` = 45 min → `Math.max(1, 45)` = 45 ✅
- `executeSave` no compara nuevo horario vs horario actual ✅
- Server action solo valida `isNaN(scheduledAt.getTime())` ✅

### Hipótesis priorizadas

**H1 (más probable) — OBS-2 conocida de Story 10.11:**
La actividad es recurrente y el usuario está en `editScope === 'all'`. En ese scope, se llama `updateActivityGroup(groupId, { title, description, duration })` que **no acepta `time`**. El cambio de horario se descarta silenciosamente. El usuario ve que "nada cambia" y lo interpreta como "no permite".

**H2 — `isPending` bloquea doble submit:**
`useTransition` deshabilita el botón durante la transición. Si el usuario hace click y el estado no se actualiza visualmente de inmediato, puede pensar que no funcionó.

**H3 — Conflicto de estado `editScope` y `date`:**
Si la actividad es recurrente con `editScope === 'single'` pero el campo `date` tiene un valor incorrecto o no se sincronizó, el server action puede recibir datos inválidos y devolver error silencioso.

**H4 — Timezone parsing:**
`new Date(`${date}T${time}:00`)` en server action — si `date` viene como `"2026-03-09"` y la hora es `"13:45"`, en Node.js (UTC por defecto en servidor) esto se parsea como UTC. Si la DB almacena en UTC y el cliente muestra en UTC-5, el horario puede parecer "incorrecto" al usuario.

## Acceptance Criteria sugeridos

- **AC1:** Cambiar el horario de una actividad no recurrente de 14:45→13:45 persiste correctamente.
- **AC2:** Cambiar el horario de una actividad recurrente con scope `'single'` de 14:45→13:45 persiste correctamente solo para esa ocurrencia.
- **AC3:** Si scope es `'all'` y el usuario cambia el horario, el cambio TAMBIÉN se aplica a todas las ocurrencias (fix del OBS-2 conocido de Story 10.11).
- **AC4:** Si el server action retorna error, el modal muestra el error claramente (no silencioso).
- **AC5:** 0 errores typecheck.
