## Problema

El usuario quiere que el 100% de su tiempo diario esté trackeado. Actualmente los "huecos" entre actividades no se registran. A una hora configurable (ej. 21:30), el sistema debe detectar esos huecos y presentarlos para registro rápido.

## Concepto

**Audit de huecos de tiempo diario.** El sistema ya conoce todos los eventos del día con sus `start`/`end`. Calcular los intervalos sin cobertura es algorítmicamente trivial. El reto es el trigger y la UI de registro rápido.

## Análisis del código existente

**Detección de gaps — algoritmo:**
```typescript
// Con getEventsForDay(events, today) ya disponible en calendar-utils.ts
function detectGaps(events: ICalendarEvent[], dayStart = 0, dayEnd = 24*60): Gap[] {
  const sorted = events
    .filter(e => !e.isAllDay)
    .sort((a, b) => a.start.getTime() - b.start.getTime())

  const gaps: Gap[] = []
  let cursor = dayStart // en minutos desde medianoche

  for (const evt of sorted) {
    const evtStartMin = evt.start.getHours() * 60 + evt.start.getMinutes()
    if (evtStartMin > cursor) {
      gaps.push({ from: cursor, to: evtStartMin })
    }
    const evtEndMin = evt.end.getHours() * 60 + evt.end.getMinutes()
    cursor = Math.max(cursor, evtEndMin)
  }
  if (cursor < dayEnd) gaps.push({ from: cursor, to: dayEnd })
  return gaps
}
```

**`createActivity` ya acepta:** `title, date, time, duration` — suficiente para registro rápido.

**Infraestructura faltante:**
- No existe tabla `user_preferences` → se necesita crear (o usar `localStorage` para MVP)
- No existe mecanismo de trigger programado → opciones:
  1. **Client-side**: `useEffect` + `setTimeout` calculado al montar la app (más simple, MVP)
  2. **Edge Function cron**: Supabase Edge Functions con `pg_cron` o programado (más robusto)

## Propuesta de implementación (2 fases)

### Fase 1 — MVP (client-side, sin infraestructura nueva)
- Al cargar el calendario, calcular si es hoy y si la hora actual pasó el umbral configurado
- Si sí: mostrar banner/panel "Tienes X min sin trackear hoy" con botón "Registrar"
- Umbral configurable en `localStorage` (clave: `closeJournalHour`, default: `"21:30"`)
- El panel se descarta con "Ignorar" y no vuelve a aparecer hasta el día siguiente

### Fase 2 — Persisted + Notificación push
- Tabla `user_preferences` en DB con `close_journal_hour`
- Notificación push en browser (Notification API) al llegar la hora
- Panel de registro rápido embebido en el calendario (no modal completo)

## UI propuesta — Panel de cierre

```
┌─────────────────────────────────────────────────────────┐
│ 🌙 Cierre del día — 1h 45min sin registrar              │
│                                                          │
│  • 10:00 – 11:30  (90 min)  [+ Registrar]               │
│  • 16:45 – 17:00  (15 min)  [+ Registrar]               │
│                                                          │
│  [Ignorar por hoy]                           [Cerrar]   │
└─────────────────────────────────────────────────────────┘
```

Al presionar `[+ Registrar]` en un gap: abre `NewActivityModal` preconfigurado con `date`, `time` (inicio del gap) y `duration` (duración del gap) ya rellenados — solo falta el título.

## Acceptance Criteria sugeridos

- **AC1:** Si la hora actual ≥ umbral configurado (default 21:30) y existen gaps > 5 min en el día actual, aparece un banner/panel en la vista de calendario.
- **AC2:** El panel lista cada gap con hora inicio, hora fin y duración.
- **AC3:** Cada gap tiene botón "Registrar" que abre `NewActivityModal` preconfigurado con la fecha, hora inicio y duración del gap.
- **AC4:** Botón "Ignorar por hoy" descarta el panel y no vuelve a aparecer en el día actual (localStorage).
- **AC5:** La hora umbral es configurable desde Settings o directamente en el panel.
- **AC6:** Gaps < 5 min no se muestran (umbral de ruido).
- **AC7:** 0 errores typecheck.
